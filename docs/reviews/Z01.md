## Findings

**F1 — BLOCKER. The audit step can turn `check` red on a commit with no dependency change.**
- **Where:** `.github/workflows/ci.yml` (audit step) and `tools/policy/audit.ts:56-81` and `:97-101`.
- **What happens:** on every push to `ccr-14987baf-i6lrsl`, `audit.ts` sends a live request to the registry. Two things fail the step:
  - a new advisory of severity low or higher for any package in scope, dev tools included (vitest, eslint, typescript and so on);
  - a registry outage that lasts past 3 tries (`E_AUDIT_FETCH`).
- **Why it blocks deploys:** the step is inside `check`, so the commit turns red. `commit_verdict` (`logic.sh:192-200`) then refuses it, and so does every later push until the dependency is fixed.
- **It can last up to 14 days.** The patched version will usually be newer than 14 days, so `age.ts` refuses it unless an exclusion is reviewed in.
- **Fix:** keep audit failing on `pull_request` runs. On `push` runs, make it report only (print the findings, exit 0), or move the push-time audit to a schedule that opens an issue rather than failing a commit. This needs a ruling against "audit on every run" in B-M30-01 logic 5; `config.ts` `CI_REQUIRED_STEPS` currently forbids an `if` on the step. Add a test that a push run with an advisory present does not fail the job.

**F2 — BLOCKER until checked (likely, not verified on this repo). `guard.yml` failures probably land on the integration branch's newest commit.**
- **Where:** `.github/workflows/guard.yml`.
- **Why I think so:** for `pull_request_target`, GitHub's docs give `GITHUB_SHA` as the last commit on the base branch. A web search result reports that the check runs land on that base SHA, not the PR head.
- **What would happen:**
  - The default branch is `ccr-14987baf-i6lrsl`, so after merge, any PR that touches a guarded file before it has its label puts a failed `guard` run on the integration branch's newest commit.
  - `commit_verdict` treats any failed run as red, and a later green rerun does not clear it.
  - So the newest commit stays undeployable until another merge lands.
- **Fix:** keep `guard.yml` out of this PR until it has been tested on a scratch repository. Or have the gate ignore the `guard` check run (a `logic.sh` change, which runs the ops e2e).

**F3 — MINOR. The 30-minute job timeout may be tight.**

- **Fix:** check the PR's real CI duration, and raise the timeout if it is near the limit. A timeout is a failed check, which blocks the deploy.

**F5 — MINOR. Racing pushes can break `age.ts`.**
- **Where:** `tools/policy/age.ts:203`.
- On a push, `age.ts` compares against the newest commit of the branch (two-dot), while `drift.ts` uses the merge base (three-dot).
- If an older commit's run starts after a newer push, it can fetch and check entries the newer commit removed. A failed fetch then turns the older commit red. Rare.
- **Fix:** read the base lockfile at `merge-base(base, HEAD)`.
